## GoFrame v2.10.3 发布：达梦 DAO 生成、MSSQL UUID、协程池动态扩缩与红黑树节点弹出，新增 loong64 架构支持

`GoFrame v2.10.3` 已发布。本版本以问题修复为主，同时补上几项实用能力：达梦 `DAO` 生成、`MSSQL UUID`、协程池动态扩缩、红黑树弹出节点，以及 `loong64` 架构支持。

完整变更：[https://github.com/gogf/gf/releases/tag/v2.10.3](https://github.com/gogf/gf/releases/tag/v2.10.3)

代码差异：[https://github.com/gogf/gf/compare/v2.10.2...v2.10.3](https://github.com/gogf/gf/compare/v2.10.2...v2.10.3)

---

## 新功能

### CLI：`gf gen dao` 支持达梦数据库

`gf gen dao` 现已支持达梦（`DM`）。达梦项目可直接生成 `DAO`，不必再手写或另找适配方案。

### MSSQL：`uniqueidentifier` 转为 `uuid.UUID`

`MSSQL` 的 `uniqueidentifier` 会映射为 `uuid.UUID`，类型更准确，业务侧处理 `UUID` 更省事。

### 协程池：可动态调整 limit / cap

`os/grpool` 支持运行时调整并发上限和容量，流量波动时不必重建整个池。

### 红黑树：支持弹出左右节点

`container/gtree` 新增弹出左、右节点能力，适合按序取出最值或做队列式消费。

### 架构：支持 loong64

为适配 `loong64`，已升级 `go-sqlite` 与 `modernc.org/libc`，龙芯环境可正常使用相关能力。

## 问题修复

### HTTP 服务 `net/ghttp`

- **TLS `GetCertificate` 回调被覆盖**：自定义证书选择逻辑可正常生效。
- **非法 JSON Body 会明确报错**：不再静默吞掉解析失败。
- **路由缓存按 HTTP Method 大小写污染**：查找前统一转大写，避免 `get` / `GET` 打到不同缓存。
- **路由查找缓存改为大小写保留的 key**：与上一修复配套，缓存命中更稳定。
- **Windows Web 管理重启只停不启**：重启后服务会真正拉起来。

### HTTP 客户端 `gclient`

补充超时配置方法，并优化客户端初始化，超时控制更直观。

### OpenAPI `net/goai`

- 对象类型 query 参数补上 `style=deepObject`、`explode=true`，嵌套对象文档与实际传参一致。
- 修复「带 `enum` 的数组元素为 `interface`」时的空指针。

### 校验 `util/gvalid`

日期规则会拦截非法格式（如 `Y-MMMM`）和非法日期（如 `2026-13-33`），不再误判为合法。

### 类型转换 `util/gconv`

- 支持基于数组的 unmarshal。
- 正确展开 `reflect.Value`，并支持指针元素切片。

### 配置 `os/gcfg`

`GetWithEnv` 会规范化配置 pattern，环境变量覆盖更稳定。

### 日志 `os/glog`

`JsonHandler` 输出扁平 `JSON`，便于直接写入 `Elasticsearch`。

### 哈希 `encoding/ghash`

`PJW64` 按 64 位宽度计算，结果符合算法定义。

### 容器 `container/gmap`

`KVMap`、`ListKVMap` 增加 `WithError` 方法，取值失败可拿到 error。

### ORM `database/gdb`

行迭代被中断时不再当成成功，避免漏数据还显示“没问题”。

### Nacos

切到上游已修复 `RpcClient` 数据竞争的提交，并发更稳。

### CLI `cmd/gf`

生成的 service 文件补上缺失指针，生成代码可直接编译使用。
