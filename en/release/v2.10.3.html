Version: 2.10.x(Latest)

GoFrame v2.10.3 Released: DM DAO Generation, MSSQL UUID, Dynamic Pool Resizing, Red-Black Tree Node Popping and loong64 Support​

GoFrame v2.10.3 has been released. This version mainly focuses on bug fixes, while adding several practical capabilities: DM DAO generation, MSSQL UUID, dynamic goroutine pool resizing, red-black tree node popping, and loong64 architecture support.

Full changelog: https://github.com/gogf/gf/releases/tag/v2.10.3

Code diff: https://github.com/gogf/gf/compare/v2.10.2...v2.10.3

New Features​

CLI: gf gen dao supports Dameng database​

gf gen dao now supports Dameng (DM). Dameng projects can generate DAO directly, with no need for manual coding or third-party adapters.

MSSQL: uniqueidentifier maps to uuid.UUID​

MSSQL's uniqueidentifier is now mapped to uuid.UUID, providing a more accurate type and making UUID handling easier on the business side.

Goroutine pool: dynamic limit / cap adjustment​

os/grpool supports adjusting the concurrency limit and capacity at runtime, so you don't need to rebuild the whole pool when traffic fluctuates.

Red-black tree: pop left / right nodes​

container/gtree adds the ability to pop the leftmost and rightmost nodes, useful for fetching extremes in order or consuming nodes like a queue.

Architecture: loong64 support​

To support loong64, go-sqlite and modernc.org/libc have been upgraded, so related capabilities work properly on Loongson platforms.

Bug Fixes​

HTTP server net/ghttp​

  • TLS GetCertificate callback was overwritten: custom certificate selection logic now works as expected.
  • Invalid JSON body now reports an error explicitly: parse failures are no longer silently swallowed.
  • Route cache polluted by HTTP method casing: method names are normalized to uppercase before lookup, so get and GET no longer hit different caches.
  • Route lookup cache uses a case-preserving key: paired with the previous fix, making cache hits more stable.
  • Windows web management restart stopped but never started: the service is now actually brought back up after a restart.

HTTP client gclient​

Added timeout configuration methods and optimized client initialization, making timeout control more straightforward.

OpenAPI net/goai​

  • Object-typed query parameters now include style=deepObject and explode=true, keeping docs consistent with actual parameter passing for nested objects.
  • Fixed a nil pointer when array elements with enum are of type interface.

Validation util/gvalid​

The date rule now rejects invalid formats (such as Y-MMMM) and invalid dates (such as 2026-13-33) instead of treating them as valid.

Type conversion util/gconv​

  • Added support for array-based unmarshalling.
  • Correctly unwraps reflect.Value and supports slices of pointer elements.

Configuration os/gcfg​

GetWithEnv now normalizes the config pattern, making environment-variable overrides more reliable.

Logging os/glog​

JsonHandler now outputs flat JSON, making it easy to write directly to Elasticsearch.

Hashing encoding/ghash​

PJW64 is now calculated at 64-bit width, so the result matches the algorithm definition.

Container container/gmap​

KVMap and ListKVMap now provide a WithError method, so an error is available when value retrieval fails.

ORM database/gdb​

An interrupted row iteration is no longer treated as successful, avoiding silent data loss with a false "everything is fine" result.

Nacos​

Switched to an upstream commit that fixes a data race in RpcClient, improving concurrency stability.

CLI cmd/gf​

Generated service files now include missing pointers, so the generated code compiles and runs directly.

Tests​

  • Expanded contrib/drivers/pgsql test coverage to the MySQL/MariaDB baseline, with 3 accompanying framework fixes. #4763 (@lingcoder)
  • Expanded gaussdb driver test coverage to the MySQL/PgSQL baseline, with 8 accompanying driver fixes. #4840 (@lingcoder)

Upgrade Guide​

go get -u github.com/gogf/gf/v2@v2.10.3

Please upgrade the CLI to the corresponding version as well. If you use any of the following features, it is recommended to verify them first:

  • HTTP routing (especially method casing and the TLS certificate callback)
  • JSON request body error handling
  • Date validation
  • gconv conversion
  • gdb scanning / iteration
  • Process restart on Windows
  • Dameng gen dao, MSSQL UUID, and grpool dynamic limiting

Questions and discussion: https://github.com/gogf/gf/issues
